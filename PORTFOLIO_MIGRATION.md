# RESONA → static portfolio site (no Lovable, no Supabase)

You are working in this repo (`ai-resonance-lab`), a Vite + React + TypeScript + Tailwind/shadcn app
originally generated by Lovable and backed by Lovable Cloud (Supabase). Goal: turn it into a
**self-contained portfolio piece** that runs with zero backend, zero running cost, and can be hosted
as static files (Netlify/Cloudflare Pages/Vercel). Keep the visual identity and all existing pages.

Work on a new git branch `portfolio-static`. Commit after each phase with a clear message.
Before each phase, briefly tell me what you will change; stop and ask me if something is ambiguous
or would delete data.

## Context: problems found in an audit

1. **RLS hole**: every migration has `"Service can manage …"` policies `FOR ALL USING (true) WITH CHECK (true)`
   with no `TO service_role`, so the anonymous public key can insert/update/delete every table and read
   `agent_keys` and private `agent_reflections`.
2. **Engine runs from every visitor's browser**: `src/hooks/useEngineRunner.ts` (used in `pages/Index.tsx`)
   calls the `engine-tick` edge function every 10 s per open tab; `verify_jwt = false`, no auth. This spawned
   ~3,656 agents for only ~231 sessions and burns AI credits.
3. `agent-register` is public with no rate limit; user-supplied `goals` flow into the AI system prompt.
4. Every hook refetches everything on any realtime change.
5. The manifesto says "No prompts. No goals." but agents have goals, a system prompt, and ~50% of
   messages come from the hard-coded `responseBank` in `engine-tick`.
6. SEO: SPA with one title for all routes, relative `og:image`, `author: Lovable`, `twitter:site: @lovaborhq`,
   682 KB `public/resona.png`, no sitemap.
7. Header: 13 nav links shown from `lg` (1024px); overflows and clips the logo up to ~1400px.
8. Contrast: `--muted-foreground` (220 10% 50%) is used ~76 times with opacity /20–/80 → 1.2–3.4:1.
9. Dead code: `src/lib/data.ts` (unused mock data); package name `vite_react_shadcn_ts`; `.env` not in `.gitignore`.

Moving off Supabase removes problems 1–4 entirely. Do not spend time patching the edge functions.

## Phase 1 — Export a data snapshot (one-time script)

- Create `scripts/export-snapshot.ts` (run with `npx tsx`). It reads `VITE_SUPABASE_URL` and
  `VITE_SUPABASE_PUBLISHABLE_KEY` from `.env` and exports the **publicly readable** tables with
  pagination (1000 rows per page):
  `agents, sessions, messages, relationships, ancestor_archetypes, archived_fractures,
  session_observer_metrics, observer_notes, observer_events, agent_reflections (archived = true only),
  ancestor_echoes, engine_state`.
  **Never export `agent_keys`.** Strip any column that looks like a key or secret.
- Write raw output to `scripts/.snapshot-raw/` (gitignored).
- Then a pruning step writes the curated snapshot to `src/data/snapshot/*.json`:
  - keep the ~150 most interesting sessions (highest `message_count`, plus every session that ended in
    `rupture` / has an archived fracture), all their messages, metrics and observer notes;
  - keep only agents referenced by kept sessions/relationships/fractures, plus the Archivist;
  - keep all archetypes; cap `observer_events` to events touching kept agents/sessions;
  - target ≤ 3 MB total JSON. Print row counts and file sizes when done.
- Run it, show me the counts, and wait for my OK before continuing.

## Phase 2 — Local data layer

- Create `src/data/repository.ts` that loads the snapshot JSON (lazy `import()` per table so the
  homepage bundle stays small) and exposes typed query functions that return the **same shapes the
  hooks return today** (reuse types from `src/integrations/supabase/types.ts` / `src/lib/*.types.ts`
  by copying the needed row types into `src/data/types.ts`).
- Rewrite every hook in `src/hooks/` and any page/component that imports `supabase` to use the
  repository instead. Remove all realtime subscriptions.
- Keep loading/error states working; keep sorting/pagination/search behaviour on the Ancestors and
  archetype pages identical.

## Phase 3 — "Live Feed" as an honest replay

- Delete `useEngineRunner`. Replace the live feed with a **replay engine** in `src/engine/replay.ts`:
  it takes archived sessions and re-plays their recorded messages and silences on a compressed
  timeline (e.g. 1 recorded minute → 3 s, silences shown as a pulsing "silence" event), cycling
  through sessions, all in memory in the browser. No randomness that invents content: only recorded data.
- Label it clearly in the UI: "Replaying the recorded archive (Feb 2026)" instead of
  "Engine running", and show the real snapshot counts instead of tick counts.
- Respect `prefers-reduced-motion` (no auto-advance animation, manual "next" button).

## Phase 4 — Remove Lovable/Supabase
